# 第 09 篇 · 工程化与发布 📦

> 本周目标：把"能跑的脚本"升级为"能让别人 `pip install` 的真正项目"。配齐项目结构 / pyproject.toml / 单元测试 / CI / 发布到 PyPI。

---

## 1. 为什么要工程化？🤔

**类比**：第 03 篇写的 `todo.py` 像一份**手写菜谱**——你自己用没问题，给别人就一脸懵。
工程化 = 把菜谱印成**菜单 + 配料表 + 烹饪流程**，任何人按照流程都能复刻。

| 没工程化 | 工程化 |
|---------|-------|
| 一个 .py 文件 | 完整目录 + pyproject.toml |
| 没有依赖清单 | 锁文件 uv.lock |
| 没有测试 | pytest + 覆盖率 |
| 没有 CI | GitHub Actions 自动测试 |
| 不能 pip install | 可发布到 PyPI |

## 2. 项目结构：src layout vs flat layout 🏗️

```
# flat layout（小项目，简单）
mytodo/
├── pyproject.toml
├── README.md
├── mytodo.py
└── tests/

# src layout（推荐，大项目）
mytodo/
├── pyproject.toml
├── README.md
├── LICENSE
├── src/
│   └── mytodo/
│       ├── __init__.py
│       ├── core.py
│       └── cli.py
└── tests/
    └── test_core.py
```

> 💡 **划重点**：用 src layout 的好处是——你**绝不会**意外 import 到当前目录的代码，必须 `pip install -e .` 后才能 import，**强制你像"用户"一样用自己的包**。

## 3. uv：现代 Python 工具链 ⚡

uv 由 ruff 同一团队（Astral）出品，用 Rust 写，比 pip / poetry 快 10-100 倍。**一个工具同时是 pip / venv / pip-tools / poetry / pyenv**。

```bash
# 安装 uv（macOS / Linux）
curl -LsSf https://astral.sh/uv/install.sh | sh

# 新建项目
uv init mytodo
cd mytodo

# 创建虚拟环境
uv venv

# 加依赖（自动改 pyproject.toml + 装包）
uv add pydantic
uv add --dev pytest ruff mypy

# 安装所有依赖（按 uv.lock 锁版本）
uv sync

# 跑命令（自动用项目的 venv）
uv run python -m mytodo
uv run pytest
```

## 4. pyproject.toml 全解 📜

```toml
# pyproject.toml
[project]
name = "mytodo"                            # PyPI 上的名字（不能重）
version = "0.1.0"                          # SemVer：主.次.补
description = "A tiny CLI todo built with Pydantic"
readme = "README.md"
requires-python = ">=3.13"
license = "MIT"                           # PEP 639：直接写 SPDX 标识；旧的 license = {text = "MIT"} 写法已弃用
license-files = ["LICENSE"]              # PEP 639：声明许可证文件
authors = [{name = "Your Name", email = "you@example.com"}]
keywords = ["todo", "cli", "pydantic"]
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
]
dependencies = [
    "pydantic>=2.0",
    "click>=8.0",
]

[project.optional-dependencies]
dev = ["pytest", "ruff", "mypy"]

[project.scripts]
mytodo = "mytodo.cli:main"                 # 命令行入口

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.ruff]
line-length = 100

[tool.pytest.ini_options]
testpaths = ["tests"]
```

> 💡 **`project.scripts`** 是发布后用户能直接在终端敲 `mytodo` 而不是 `python -m mytodo` 的关键。

## 5. ruff：项目规范的守门员 🛡️

```bash
uv add --dev ruff
uv run ruff check .          # 检查
uv run ruff check . --fix    # 自动修
uv run ruff format .         # 格式化（替代 black）
```

`pyproject.toml` 关键配置：

```toml
[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM", "N"]
ignore = ["E501"]            # 不限制行长（line-length 已配）
```

| 规则代码 | 含义 |
|---------|------|
| E | pycodestyle 风格错误 |
| F | pyflakes 未使用变量 |
| I | isort import 排序 |
| UP | pyupgrade 升级老语法 |
| B | flake8-bugbear 易错点 |
| SIM | 简化建议 |
| N | 命名规范 |

## 6. pytest：写测试不是负担 🧪

```python
# tests/test_core.py
import pytest
from mytodo.core import TaskList, TaskNotFound   # 第 08 篇的异常体系一起搬进包里

def test_add_task():
    tl = TaskList()
    t = tl.add("写代码")
    assert t.id == 1
    assert t.title == "写代码"

def test_done_invalid_id():
    tl = TaskList()
    with pytest.raises(TaskNotFound, match="任务不存在"):
        tl.done(999)

def test_task_not_found_is_value_error():
    # 我们的 TaskNotFound 同时继承 ValueError（向后兼容设计），
    # 所以老代码 except ValueError 依然能接住 —— 测试锁住这个行为。
    tl = TaskList()
    with pytest.raises(ValueError):
        tl.done(999)

@pytest.mark.parametrize("title,ok", [
    ("hello", True),
    ("", False),
    ("x" * 200, False),
])
def test_title_validation(title, ok):
    tl = TaskList()
    if ok:
        tl.add(title)
    else:
        with pytest.raises(Exception):
            tl.add(title)
```

跑：

```bash
uv run pytest -v
uv run pytest --cov=mytodo --cov-report=term-missing   # 覆盖率
```

### 🎯 动手练习 9.1
给 `TaskList.done` 写 3 个测试：成功、id 不存在、id 传了字符串。

<details>
<summary>👀 参考答案</summary>

```python
def test_done_ok():
    tl = TaskList(); tl.add("x")
    tl.done(1)
    assert tl.tasks[0].status == "done"

def test_done_not_found():
    tl = TaskList()
    with pytest.raises(TaskNotFound):
        tl.done(42)

def test_done_str_id():
    tl = TaskList(); tl.add("x")
    # ⚠️ 别期望 TypeError！类型注解不做运行时检查（第 08 篇划过重点）。
    #    done("1") 里 "1" == 1 永远不成立，循环走完抛的是 TaskNotFound。
    #    这个测试故意写成"错误类型不会炸、只会找不到"，逼你记住注解是给人看的。
    with pytest.raises(TaskNotFound):
        tl.done("1")
```

> 💡 想让 `done("1")` 真的抛 TypeError？在 `done` 开头加显式检查：
> ```python
> if not isinstance(tid, int):
>     raise TypeError(f"tid 必须是 int，收到 {type(tid).__name__}")
> ```
> 运行时校验交给 Pydantic（`TypeAdapter(int).validate_python(tid)`）或显式 isinstance —— 注解本身永远拦不住任何东西。
</details>

```yaml
repos:

    rev: v0.5.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

```

## 8. GitHub Actions CI：每次推送自动测试 🤖

`.github/workflows/test.yml`：

```yaml
name: test
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.13", "3.14", "3.15"]
    steps:
      - uses: actions/checkout@v4
      - name: Install uv
        uses: astral-sh/setup-uv@v3
      - name: Setup Python ${{ matrix.python }}
        run: uv python install ${{ matrix.python }}
      - name: Install deps
        run: uv sync --all-extras
      - name: Lint
        run: uv run ruff check .
      - name: Type check
        run: uv run mypy src
      - name: Test
        run: uv run pytest --cov=mytodo
```

每次 `git push` 或开 PR，GitHub 会自动在 3 个 Python 版本下跑全套检查，绿勾才能合并。

## 9. SemVer：版本号怎么打 🔢

`MAJOR.MINOR.PATCH` —— 例如 `1.4.2`。

| 改动类型 | 升哪一位 | 例子 |
|---------|---------|------|
| **不兼容**改动（删了 API、改了行为） | MAJOR | 1.x → 2.0.0 |
| 新增功能（向后兼容） | MINOR | 1.4 → 1.5.0 |
| Bug 修复（向后兼容） | PATCH | 1.4.2 → 1.4.3 |

> 💡 0.x.y 是"试验期"，可以随便改。一旦发 1.0.0，就要遵守上面的规则。

## 10. 实战：发布 mytodo 到 TestPyPI 🚀

[TestPyPI](https://test.pypi.org/) 是 PyPI 的"练习场"，正式发布前先在这里跑一遍。

### 第零步：把包代码填进骨架

第 2 节的目录结构里有 `core.py` 和 `cli.py` 两个文件，`pyproject.toml` 的入口写的是 `mytodo = "mytodo.cli:main"` —— **发布前这两个文件必须真实存在**，否则 `pip install` 之后 `mytodo` 命令直接报错。

```python
# src/mytodo/core.py —— 第 08 篇的模型原样搬进来
from pydantic import BaseModel, Field, ValidationError
from datetime import datetime
from pathlib import Path
from typing import Literal

class TodoError(Exception): ...
class TaskNotFound(TodoError, ValueError): ...

class Task(BaseModel):
    id: int
    title: str = Field(min_length=1, max_length=80)
    status: Literal["todo", "doing", "done"] = "todo"
    created_at: datetime = Field(default_factory=datetime.now)

class TaskList(BaseModel):
    tasks: list[Task] = []

    def add(self, title: str) -> Task: ...
    def list(self) -> list[Task]: ...
    def done(self, tid: int) -> None: ...
    def remove(self, tid: int) -> None: ...
    def save(self, path: Path) -> None: ...

    @classmethod
    def load(cls, path: Path) -> "TaskList": ...
    # ↑ 方法体从第 08 篇实战 11 复制，一行都不用重写 —— 这就是先写脚本再包层的顺序红利
```

```python
# src/mytodo/cli.py —— click 入口（pyproject 的 project.scripts 指的就是这里的 main）
import click
from pathlib import Path
from pydantic import ValidationError
from .core import TaskList, TaskNotFound

DB = Path("todos.json")

def _load() -> TaskList:
    return TaskList.load(DB)

@click.group()
def main():
    """mytodo —— 用 Pydantic 写的极简命令行 TODO。"""

@main.command()
@click.argument("title")
def add(title: str):
    """添加一条任务。"""
    tl = _load()
    try:
        t = tl.add(title)
    except ValidationError as e:
        raise click.ClickException(f"校验失败：{e.errors()[0]['msg']}")
    tl.save(DB)
    click.echo(f"已添加 #{t.id}: {t.title}")

@main.command("list")
def list_():
    """列出全部任务。"""
    for t in _load().list():
        mark = "x" if t.status == "done" else " "
        click.echo(f"[{mark}] {t.id}. {t.title}")

@main.command()
@click.argument("tid", type=int)     # click 负责把字符串转 int，转不动直接报错
def done(tid: int):
    """按 id 标记完成。"""
    tl = _load()
    try:
        tl.done(tid)
    except TaskNotFound as e:
        raise click.ClickException(str(e))
    tl.save(DB)
    click.echo(f"已完成 #{tid}")

@main.command()
@click.argument("tid", type=int)
def remove(tid: int):
    """按 id 删除任务。"""
    tl = _load()
    try:
        tl.remove(tid)
    except TaskNotFound as e:
        raise click.ClickException(str(e))
    tl.save(DB)
    click.echo(f"已删除 #{tid}")

if __name__ == "__main__":
    main()
```

```python
# src/mytodo/__init__.py —— 让 from mytodo import TaskList 也能用
from .core import Task, TaskList, TaskNotFound, TodoError

__all__ = ["Task", "TaskList", "TodoError", "TaskNotFound"]
__version__ = "0.1.0"
```

本地先验证再发布：

```bash
uv pip install -e .
mytodo add "发布前自测"
mytodo list
mytodo done 1
mytodo --help          # 能看到四个子命令的帮助 —— 这一步过了才有脸发布
```

> 💡 注意分工：**core.py 不知道 click 的存在**（纯模型 + 业务异常），cli.py 只做参数解析和输出。这样测试（第 6 节）全部打在 core 上、不需要模拟终端，将来想换 typer 或加个 Web API 也只动入口层。
