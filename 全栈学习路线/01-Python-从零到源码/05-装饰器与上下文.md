# 第 05 篇 · 装饰器与上下文管理器 🎁

> 本周目标：能用装饰器和上下文管理器写出可复用、可测试的工具，并搭起一套自己的异常体系。
> 
> 这一周，你会读到很多写了 5 年 Python 的人都讲不清的概念 — **闭包、装饰器、上下文管理器**。
> 别紧张：它们只是**几个朴素的想法**叠在一起。一旦想通，你的代码就会变得"安静而强大"。

## 1. 函数是一等公民 🥇

**类比**：在 Python 里，函数就是个"普通对象" — **能装进变量、能当参数、能当返回值**，跟数字、字符串一样普通。

```python
def hello():
    return "hi"

f = hello             # 把函数本身赋给变量（不要写 ()）
print(f())            # hi

def call(fn):         # 把函数当参数
    return fn()
print(call(hello))    # hi

def factory():        # 把函数当返回值
    def inner():
        return "from inner"
    return inner

g = factory()
print(g())            # from inner
```

> 💡 这个能力是装饰器的基石。**记住**：不带 `()` 是"传函数本身"，带 `()` 是"调用并取结果"。

---

## 2. 闭包：函数把"出生时的环境"打包带走 📦

**类比**：闭包就像一个**带便当盒的人** — 走到哪儿都带着自己的环境（外层变量）。

```python
def make_counter():
    count = 0           # 外层变量
    def inner():
        nonlocal count  # 声明：要修改外层变量
        count += 1
        return count
    return inner

c = make_counter()
print(c(), c(), c())    # 1 2 3
```

`inner` 离开了 `make_counter`，但仍然能访问 `count` — 这就是**闭包**。

### 闭包的典型用例
```python
def make_adder(n):
    def add(x):
        return x + n
    return add

add5 = make_adder(5)
add10 = make_adder(10)
print(add5(3), add10(3))   # 8 13
```

> 💡 一句话：**闭包 = 函数 + 它所记住的外部变量**。

## 3. 装饰器：给函数"装个外壳" 🎀

**类比**：装饰器就是**手机壳** — 不改原手机，但加上保护、卡槽、支架等附加功能。

### 3.1 不用 `@` 的版本（先理解）
```python
def shout(fn):
    def wrapper():
        return fn().upper() + "!!!"
    return wrapper

def hello():
    return "hi"

hello = shout(hello)         # 用包装后的替换原函数
print(hello())               # HI!!!
```

### 3.2 用 `@` 的版本（语法糖）
```python
def shout(fn):
    # shout 是「装饰器」：接收一个函数，返回一个新函数。
    # 参数 fn 是原函数对象（这里就是 hello），不是调用结果。
    def wrapper():
        # 闭包里引用 fn —— 走 LEGB 的 E 层（enclosing）。
        # 调用 fn() 得到原函数的返回值，再链式加工。
        return fn().upper() + "!!!"
    # 返回的是「新函数对象」，不是 wrapper() 的调用结果。
    # 如果误写成 return wrapper()，会立刻执行并炸（hello 还没定义完就调了）。
    return wrapper


@shout                # 等价于 hello = shout(hello)
def hello():
    return "hi"

print(hello())        # HI!!!  ← 实际调用的是 wrapper()
```

> 💡 `@xxx` 写在 `def f` 上一行，就是 `f = xxx(f)` 的简写。

## 4. 第一个实用装饰器：@timer ⏱️

```python
import time
from functools import wraps

def timer(fn):
    @wraps(fn)                       # 保留原函数的名字 / 文档 / __wrapped__
    def wrapper(*args, **kwargs):    # 通用：接任何参数，原样转发
        start = time.perf_counter()  # 单调高精度计时器，见下文第 1 条
        result = fn(*args, **kwargs) # 调用原函数，先存结果
        cost = time.perf_counter() - start
        print(f"{fn.__name__} 用时 {cost:.4f}s")
        return result                # 最后才返回，保证结果不被计时逻辑吃掉
    return wrapper

@timer
def slow_sum(n):
    return sum(range(n))

print(slow_sum(1_000_000))
# slow_sum 用时 0.0123s
# 499999500000
```

> 💡 **`@wraps`** 极重要 — 不加的话，被装饰的函数会"丢名字"，调试时一脸懵。

## 5. 带参数的装饰器：再套一层 🎚️

需求：让 `@retry(times=3)` 自动重试 3 次。

```python
import time
import random
from functools import wraps


def retry(times=3, base_delay=0.5, max_delay=30.0, exceptions=(Exception,)):
    """重试装饰器工厂。

    参数:
        times:      最多尝试次数（含首次），times=1 表示不重试。
        base_delay: 首次重试前的等待基数（秒）。
        max_delay:  单次等待的上限（秒），防止指数增长失控。
        exceptions: 只对这些异常重试；其他异常立刻穿透。
                    默认 Exception —— 注意它不含 KeyboardInterrupt / SystemExit。
    """
    # 防御性校验：参数写错时在「装饰时」就报错，而不是等运行时才出怪事
    if times < 1:
        raise ValueError("times 必须 >= 1")
    if base_delay < 0 or max_delay < 0:
        raise ValueError("delay 不能为负")

    def decorator(fn):
        @wraps(fn)   # 保留原函数的 __name__ / __doc__ / __wrapped__
        def wrapper(*args, **kwargs):
            # 从 1 开始计数，日志里直接写 "第 2/3 次"，读的人不用心算
            for attempt in range(1, times + 1):
                try:
                    return fn(*args, **kwargs)   # 成功立即返回，不再重试

                except exceptions as e:
                    # 最后一次失败：不再等待，直接把原始异常抛出。
                    # 用裸 raise 而不是 raise RuntimeError(...)：
                    #   - 保留原始 traceback 和异常类型
                    #   - 调用方看到的是真实的 ValueError / ConnectionError
                    #   - 不用额外写 raise ... from e 来串因果链
                    if attempt == times:
                        raise

                    # 指数退避：0.5 → 1 → 2 → 4 ...，并封顶在 max_delay
                    # 目的：给下游足够的恢复时间；固定间隔在长故障下等于没重试
                    delay = min(base_delay * (2 ** (attempt - 1)), max_delay)

                    # 抖动：在 [0, delay] 内随机
                    # 目的：打散「所有客户端同时失败、同时重试」造成的脉冲，
                    #       否则下游刚恢复就被一波重试打爆（雪崩）
                    sleep_for = random.uniform(0, delay)

                    print(f"{fn.__name__} 第 {attempt}/{times} 次失败："
                          f"{type(e).__name__}: {e}，{sleep_for:.2f}s 后重试")
                    time.sleep(sleep_for)

            # 理论上不可达：最后一次失败已在循环内 raise
            # 保留这行是为了让静态检查器和阅读者都明确「函数一定返回或抛异常」
            raise RuntimeError(f"{fn.__name__} 重试耗尽")  # pragma: no cover

        return wrapper

    return decorator

# ---------- 使用示例 ----------

@retry(times=3, base_delay=0.2, exceptions=(ValueError,))
def maybe_fail():
    if random.random() < 0.7:
        raise ValueError("network error")
    return "ok"

print(maybe_fail())
```

**结构**：装饰器**带参数 = 三层函数**。`retry(...)` 返回真正的装饰器 `decorator`。

## 6. 类装饰器与基于类的装饰器 🏗️

```python
from functools import wraps


class CountCalls:
    def __init__(self, fn):
        # 关键一行：wraps(fn) 返回一个「更新器」，wraps(fn)(self) 等价于
        # update_wrapper(self, fn) —— 把 fn 的 __name__ / __doc__ / __module__ /
        # __qualname__ / __dict__ 复制到 self 上，并设置 self.__wrapped__ = fn。
        # 放在最前面是刻意的：update_wrapper 会 update self.__dict__，
        # 先做这一步，后面 self.fn / self.n 就不会被 fn 的同名属性意外覆盖。
        wraps(fn)(self)

        # 保存原函数。__call__ 里靠它真正执行。
        self.fn = fn

        # 计数器。类装饰器最大的好处：状态天然存在实例属性上，
        # 不需要像函数装饰器那样用 nonlocal 或可变默认参数来「藏」状态。
        self.n = 0

    def __call__(self, *args, **kwargs):
        # 每次「调用」都走这里。self.n 是跨调用累积的，因为 greet 现在
        # 指向的就是这个 CountCalls 实例，实例活得和模块一样久。
        self.n += 1
        print(f"{self.fn.__name__} 被调用第 {self.n} 次")
        return self.fn(*args, **kwargs)


@CountCalls                      # 等价于 greet = CountCalls(greet)
def greet(name):
    print(f"hi, {name}")


greet("a"); greet("b")
# greet 被调用第 1 次
# hi, a
# greet 被调用第 2 次
# hi, b
```

> 💡 类装饰器靠 `__call__` 让实例"像函数一样"被调用。

## 7. 内置好用的装饰器 🛠️

### `@lru_cache`：自动缓存
```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    # maxsize=None 表示「不限制缓存大小」——等价于纯 memoization，
    # 缓存字典可以无限增长，永不淘汰。
    # 若写 maxsize=128，则用 LRU 策略：超过 128 条时淘汰最久未用的。
    # 对 fib 这种「每个 n 只算一次、n 范围有限」的场景，None 最合适。
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
print(fib(50))     # 12586269025  极快（没有 cache 会跑到天荒地老）
```

### `partial`：固定部分参数
```python
from functools import partial


def power(base, exp):
    return base ** exp


# partial(power, exp=2) 返回一个新的可调用对象：
#   - 把 power 和「预置参数」绑在一起，但不执行 power
#   - 调用时传进来的参数，会和预置参数合并后转给 power
# 用关键字 exp=2 预置，所以调用方只需要传 base：
square = partial(power, exp=2)
cube = partial(power, exp=3)

print(square(5), cube(2))   # 25 8
```

## 8. 上下文管理器：自动清理的助手 🧹

**类比**：上下文管理器像**酒店退房系统** — 你"入住" → 用完就 "退房"，不会忘记关灯关门。

```python
with open("a.txt", "w") as f:
    f.write("hi")
# 离开 with 块，无论是否报错，f 都会被关闭
```

### 自定义：实现 `__enter__` / `__exit__`
```python
import time
class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                        # 这就是 as 后面的那个对象
    def __exit__(self, exc_type, exc_val, tb):
        self.cost = time.perf_counter() - self.start
        print(f"耗时 {self.cost:.4f}s")
        # return True  # 返回 True 会"吞掉"异常，谨慎使用
with Timer() as t:
    sum(range(10_000_000))         # 结果没被使用 —— 但计时照样有效
# 耗时 0.1234s
```

| 方法 | 作用 |
|------|------|
| `__enter__` | 进入 with 时执行，返回值绑定到 as |
| `__exit__` | 离开时执行，3 个参数收异常信息 |

## 9. `@contextmanager`：偷懒写上下文管理器 ⚡

```python
from contextlib import contextmanager
import time


@contextmanager
def timer(label="任务"):
    # yield 之前的代码 = __enter__
    start = time.perf_counter()

    try:
        # yield 把控制权交回 with 块。
        # yield 后面如果写值（如 yield start），那个值就是 `as` 后面的对象；
        # 这里 yield 不带值，等价于 `with timer(...) :` 不接 as。
        yield                       # ← yield 之前是 enter，之后是 exit

    finally:
        # finally 保证「正常结束」和「with 体抛异常」两条路都执行到这里。
        # 这正对应手写类里 __exit__ 的语义：无论成败都要跑清理/统计。
        # 不写 try/finally 的话，with 体一抛异常，这行就永远不执行了。
        print(f"{label} 耗时 {time.perf_counter() - start:.4f}s")


with timer("求和"):
    sum(range(10_000_000))
```

> 💡 `yield` 把函数"切两段"。`with` 进入时跑 yield 之前，退出时跑 yield 之后。

## 10. 异常处理体系 🚨

```python
try:
    n = int(input("数字："))       # 可能 ValueError：输入非数字
    print(10 / n)                  # 可能 ZeroDivisionError：n 为 0

except ValueError:
    # 第一个匹配的 except 生效后，后续 except 不再检查。
    # 顺序很重要：具体的异常写在前面，宽泛的写在后面。
    print("不是有效数字")

except ZeroDivisionError:
    print("除以零了")

except Exception as e:
    # 兜底：捕获所有未被上面两个匹配的「常规异常」。
    # 用 as e 拿到异常实例，才能打印具体信息；不用就丢掉细节。
    # 注意 Exception 不含 KeyboardInterrupt / SystemExit（它们继承 BaseException）。
    print("其他错误", e)

else:
    # 只有 try 块「完全正常跑完」才执行。
    # 等价于「把不该被 except 捕获的后续逻辑放这里」——
    # 如果写在 try 里，这段代码抛的异常会被上面的 except 误捕。
    print("没异常才执行")

finally:
    # 无论正常、异常、还是 except 里再次抛异常，都执行。
    # 用来放清理逻辑：关文件、释放锁、回滚事务。
    # 不应在 finally 里 return / raise —— 会覆盖 try 的结果或异常。
    print("无论如何都执行（清理）")
```

| 子句 | 何时执行 |
|------|---------|
| `try` | 主代码 |
| `except` | 出错时 |
| `else` | 没出错时 |
| `finally` | 永远执行（清理资源） |

### 自定义异常
```python
class InsufficientFundsError(Exception):
    """余额不足"""

def withdraw(balance, n):
    if n > balance:
        raise InsufficientFundsError(f"想取 {n}，只有 {balance}")
    return balance - n

try:
    withdraw(100, 200)
except InsufficientFundsError as e:
    print("被捕获：", e)
```

### 异常链（raise from）
```python
try:
    int("abc")
except ValueError as e:
    raise RuntimeError("解析配置失败") from e
# 报错信息会同时显示原始 ValueError 和 RuntimeError
```

> 💡 **不要 catch 所有异常然后 pass** — 这是工程灾难。要么处理，要么让它抛上去。

## 11. 实战 1：手写 5 个装饰器 ✋

```python
import time
import warnings
import inspect
from functools import wraps


# ============ 1. timer ============
def timer(fn):
    """计时装饰器：成功或失败都报告耗时。"""
    @wraps(fn)
    def wrapper(*a, **kw):
        s = time.perf_counter()
        try:
            return fn(*a, **kw)
        finally:
            # 用 finally 而不是「函数体后」，保证异常路径也打印耗时。
            # 失败调用的耗时往往才是排查重点。
            print(f"[timer] {fn.__name__} {time.perf_counter() - s:.4f}s")
    return wrapper


# ============ 2. retry ============
def retry(times=3, exceptions=(Exception,), base_delay=0.0):
    """重试装饰器。

    参数:
        times:      最多尝试次数（含首次）。
        exceptions: 只对这些异常重试；其他异常立刻穿透。
        base_delay: 指数退避的基数（秒），0 表示不等待。
    """
    def deco(fn):
        @wraps(fn)
        def wrapper(*a, **kw):
            for i in range(times):
                try:
                    return fn(*a, **kw)
                except exceptions as e:
                    # 最后一次失败：在 except 块内裸 raise。
                    # 关键：裸 raise 必须和 except 处于同一活跃作用域，
                    # 否则会抛 RuntimeError: No active exception to reraise。
                    if i == times - 1:
                        raise
                    print(f"第 {i + 1}/{times} 次失败：{type(e).__name__}: {e}")
                    if base_delay:
                        # 指数退避：给下游恢复时间；固定间隔在长故障下等于没重试
                        time.sleep(base_delay * 2 ** i)
        return wrapper
    return deco


# ============ 3. cache ============
def cache(fn):
    """手写缓存：参数元组做键，支持位置和关键字参数。"""
    store = {}

    @wraps(fn)
    def wrapper(*a, **kw):
        # 键 = (位置参数元组, 排好序的关键字参数元组)
        # 比 json.dumps 快，且不会因为 dict 顺序不同撞成不同键。
        # 参数名都是 str，sorted 只按名字比较，不会碰 value。
        key = (a, tuple(sorted(kw.items())))
        try:
            hash(key)
        except TypeError:
            # 参数里有不可哈希对象（list/dict/set）→ 缓存不了，直接放行。
            # 另一种策略是抛错提醒调用方，看业务需要。
            return fn(*a, **kw)

        if key not in store:
            store[key] = fn(*a, **kw)
        return store[key]

    # 暴露两个辅助接口，方便调试和测试
    wrapper.cache_clear = store.clear
    wrapper.cache_size = lambda: len(store)
    return wrapper


# ============ 4. deprecated ============
def deprecated(reason=""):
    """标记弃用：用 warnings.warn 而不是 print。"""
    def deco(fn):
        @wraps(fn)
        def wrapper(*a, **kw):
            warnings.warn(
                f"{fn.__name__} 已弃用：{reason}",
                DeprecationWarning,
                # stacklevel=2 让警告指向调用方代码，而不是 wrapper 内部。
                # 这是警告能不能帮到人的关键。
                stacklevel=2,
            )
            return fn(*a, **kw)
        return wrapper
    return deco


# ============ 5. validate ============
def validate(**rules):
    """参数校验：用 inspect.signature 统一处理位置参数和关键字参数。"""
    def deco(fn):
        sig = inspect.signature(fn)

        @wraps(fn)
        def wrapper(*a, **kw):
            # bind 把位置参数和关键字参数一次性归到参数名上，
            # 之后按名字校验，位置传参的也能查到。
            # 没传的参数不会出现在 bound.arguments 里 —— 默认值不校验。
            bound = sig.bind(*a, **kw)
            for k, t in rules.items():
                if k in bound.arguments:
                    v = bound.arguments[k]
                    if not isinstance(v, t):
                        raise TypeError(
                            f"{k} 必须是 {t.__name__}，"
                            f"收到 {type(v).__name__}"
                        )
            return fn(*a, **kw)
        return wrapper
    return deco


# ============ 使用示例 ============

# 正确顺序：cache 在外、timer 在内。
# 只有「缓存未命中」时 timer 才执行 —— 不会因为缓存命中而重复打印。
@cache
@timer
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


@validate(n=int)
def square(*, n):
    return n * n


@validate(n=int)
def add(n, m=1):        # 允许位置调用
    return n + m


@retry(times=3, exceptions=(ValueError,), base_delay=0.1)
def flaky(attempt_state={"n": 0}):
    attempt_state["n"] += 1
    if attempt_state["n"] < 3:
        raise ValueError("网络抖动")
    return "ok"


if __name__ == "__main__":
    print("=== fib(10) 首次：每个唯一 n 打一次 timer ===")
    print("结果：", fib(10))
    print()
    print("=== fib(10) 再调：全命中缓存，timer 不触发 ===")
    print("结果：", fib(10))
    print()
    print("=== validate：位置参数也能校验 ===")
    print("square(n=5) =", square(n=5))
    print("add(3)      =", add(3))
    for call in (lambda: square(n="x"), lambda: add("x")):
        try:
            call()
        except TypeError as e:
            print("捕获 TypeError:", e)
    print()
    print("=== retry：前两次失败，第三次成功 ===")
    print("flaky() =", flaky())
```

## 12. 实战 2：文件操作上下文管理器 📂

```python
import os
from contextlib import contextmanager
from pathlib import Path


@contextmanager
def safe_writer(path, encoding="utf-8", fsync=False, newline="\n"):
    """原子写入：写临时文件，成功才 rename 覆盖原文件。

    参数:
        fsync:   True 时在 rename 前把数据刷到磁盘，防断电丢内容。
                 默认 False —— 大多数配置场景不需要，数据库/关键数据要开。
        newline: 统一用 \\n，避免 Windows 上重写后整文件 diff 噪音。
    """
    path = Path(path)

    # 用 with_name 而不是 with_suffix：语义是「在文件名末尾拼 .tmp」，
    # 不依赖 suffix 的解析规则，对 archive.tar.gz 这类多后缀更直观。
    tmp = path.with_name(path.name + ".tmp")

    try:
        # with 管理文件关闭：正常退出、异常退出都保证 close 被调，
        # 不用手动写两次 f.close()。
        with tmp.open("w", encoding=encoding, newline=newline) as f:
            yield f

            # 只有 fsync 时才 flush + fsync。注意必须在 close 之前，
            # 因为 close 之后 fd 就失效了。
            if fsync:
                f.flush()
                os.fsync(f.fileno())

        # with 正常退出 = 文件已关闭 = 数据已交给 OS。
        # 此时才 rename，失败的话原文件完全没动过。
        tmp.replace(path)

    except BaseException:
        # 用 BaseException 而不是 Exception：
        # KeyboardInterrupt / SystemExit 时也要清理 tmp，
        # 否则 Ctrl+C 会留下半截 .tmp 文件。
        # 但不要在 except 里吞异常 —— 清理完必须 raise。
        try:
            tmp.unlink(missing_ok=True)
        except OSError:
            pass          # 清理失败不掩盖原始异常
        raise


# 使用示例
if __name__ == "__main__":
    with safe_writer("config.json") as f:
        f.write('{"debug": true}\n')
```

## 13. 实战 3：安全的资源释放 🔒

```python
from contextlib import contextmanager


class FakeDB:
    def __init__(self):
        self.connected = False

    def connect(self):
        self.connected = True
        print("DB 连接")

    def close(self):
        self.connected = False
        print("DB 关闭")

    def query(self, sql):
        print("执行：", sql)


@contextmanager
def db_session():
    db = FakeDB()
    # ⚠️ connect() 放在 try 外面是刻意的：
    # 连接本身就失败 → 没有可关闭的资源 → 不该进 finally 调 close。
    # 如果 connect 内部「部分成功」（建了 TCP 但认证失败），
    # 清理逻辑应由 connect 自己负责，不是调用方。
    db.connect()
    try:
        # yield 之前 = __enter__，这里把 db 交给 as 后面的变量。
        yield db
    finally:
        # finally 而不是「yield 之后」：with 体抛异常时，
        # 异常会被 throw 回 yield 处，只有 finally 能保证 close 执行。
        # 这是连接泄漏的分水岭 —— 少了 try/finally，一次异常就漏一个连接。
        db.close()


with db_session() as db:
    db.query("SELECT * FROM users")
    # raise RuntimeError("故意出错")   # 即使报错，DB 也会关
```
