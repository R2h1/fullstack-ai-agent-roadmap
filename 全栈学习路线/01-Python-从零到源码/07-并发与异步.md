# 第 07 篇 · 并发与异步 🚦

> 本周目标：搞清"并发 vs 并行"、"线程 vs 进程 vs 协程"，能写出比同步快约 9 倍的异步爬虫，理解为什么 Python 多线程做 CPU 密集任务**没用**。

---

## 1. 并发 vs 并行：不是一回事 ⚖️

**类比**：
- **并发（concurrency）**：一个厨师同时煮面、炒菜、烧汤，他在三口锅之间**来回切换**（一个时刻只动一锅）。
- **并行（parallelism）**：三个厨师**同时**各炒一锅菜。

| 概念             | 同时刻执行的任务数 | 关键词        | Python 工具           |
| -------------- | --------- | ---------- | ------------------- |
| 并发 Concurrency | 1 个（快速切换） | 协程 / 单核多线程 | asyncio / threading |
| 并行 Parallelism | 多个        | 多核 / 多机    | multiprocessing     |

> 💡 **划重点**：并发是"看起来同时"，并行是"真的同时"。

---

## 2. GIL：Python 多线程的"紧箍咒" 🔒

**一句话**：CPython 解释器有一把全局锁（**G**lobal **I**nterpreter **L**ock），同一时刻只允许**一个线程**执行 Python 字节码。

**类比**：办公室只有一支唯一的笔（GIL），不管你雇 10 个会计（线程），只有拿到笔的人能写账。

| 任务类型 | 多线程能加速吗？ | 为什么 |
|---------|----------------|-------|
| **CPU 密集**（算数学） | ❌ 不能 | 锁住 GIL 自己跑，其他线程在等 |
| **IO 密集**（爬虫、读文件） | ✅ 能 | 等 IO 时会释放 GIL，其他线程趁机跑 |

> 💡 **结论**：CPU 密集用 `multiprocessing`（每个进程一把锁，互不影响）；IO 密集用 `threading` 或 `asyncio`。

## 3. threading：一行代码起一个线程 🧵

```python
import threading
import time


def worker(name):
    print(f"{name} 开始")
    time.sleep(1)              # 模拟 IO：释放 GIL，让另一个线程真正并行
    print(f"{name} 结束")


# 创建线程对象，但此时什么也没发生 —— 只是记录了「要执行哪个函数、传什么参数」
t1 = threading.Thread(target=worker, args=("A",))
t2 = threading.Thread(target=worker, args=("B",))

t1.start(); t2.start()         # 同时启动
# start() 才真正创建 OS 线程并开始执行 worker。
# ⚠️ args 必须是元组：("A",) 逗号不能省；写成 ("A") 是字符串，会被拆成三个字符。
# ⚠️ start() 立刻返回，不等 worker 跑完 —— 主线程继续往下走。

t1.join();  t2.join()          # 等两个都跑完
# join() 阻塞主线程，直到对应线程结束。
# 顺序无关紧要：先等 t1 还是 t2，总耗时都是「两个线程的 max」≈ 1 秒。
# 不写 join 的后果：主线程可能先跑完，程序退出，线程被强制杀死

print("主线程退出")
```

**运行结果**（顺序可能不同）：
```
A 开始
B 开始
（暂停 1 秒）
A 结束
B 结束
主线程退出
```

总耗时约 **1 秒**，而不是 2 秒（IO 等待时切换）。

### Lock：保护共享资源

```python
import threading

counter = 0                  # 全局变量，所有线程共享
lock = threading.Lock()      # 模块级锁，所有线程共享「同一个」锁对象


def add():
    global counter           # 必须声明：函数内有赋值，不声明会变成局部变量（LEGB 规则 1）
    for _ in range(100_000):
        with lock:                     # 进入临界区，其他线程要等
            # with 等价于 acquire() + try/finally: release()，
            # 即使 counter += 1 抛异常，锁也会释放 —— 手写 acquire/release 容易漏。
            counter += 1


# 列表推导式创建 10 个线程对象，此时都还没启动
threads = [threading.Thread(target=add) for _ in range(10)]

for t in threads: t.start()  # 依次启动，10 个线程并发执行 add()
for t in threads: t.join()   # 等全部结束

print(counter)                          # 1000000 ✅
```

不加锁的话，`counter += 1` 不是原子操作（读→加→写），多个线程会"踩脚"导致最终值小于 100 万。

### Queue：线程安全的传话筒

```python
import threading, queue, time

q = queue.Queue()

def producer(n):
    for i in range(n):
        q.put(i)
        print(f"生产 {i}")
        time.sleep(0.1)
    q.put(None)                     # 生产完才放哨兵

def consumer():
    while True:
        item = q.get()
        if item is None:
            q.task_done()           # 哨兵也标记完成（配合 join 语义）
            break
        print(f"消费 {item}")
        q.task_done()


t = threading.Thread(target=consumer, daemon=True)
t.start()

producer(5)                         # 生产者可在主线程，也可另开线程
t.join()                            # ← 关键：等消费者拿到哨兵、正常退出
print("主线程退出，队列剩余:", q.qsize())
```

## 4. multiprocessing：绕过 GIL 的方法 🚀

`multiprocessing` 启动**真正的子进程**，每个进程有自己的解释器和 GIL。

```python
from multiprocessing import Pool
import time


def cpu_work(n):
    # 纯 CPU 计算，没有任何 IO。这正是 multiprocessing 的主场：
    # 每个进程有独立的解释器和 GIL，能真正并行利用多核。
    # 换成 threading 的话，GIL 会让这行和单线程一样慢。
    return sum(i * i for i in range(n))


if __name__ == "__main__":             # Windows/Mac 必须有这一行
    # 没有这行会怎样：spawn 模式下，子进程启动时会重新 import 主模块，
    # 主模块顶层的代码（包括 Pool(4) 这段）会再执行一次 →
    # 无限递归创建进程，直到系统崩溃（RuntimeError / 内存耗尽）。
    # Linux 默认 fork，不受这个限制；但为了跨平台，一律加上。

    nums = [10_000_000] * 4

    t = time.time()                     # ⚠️ 测耗时更准的是 time.perf_counter()——
                                        #    time.time() 会受系统时钟调整影响，精度也低
    with Pool(4) as p:                  # 4 个进程
        # map 是阻塞的：所有任务跑完才返回，结果是 list（不是迭代器）。
        # 想要惰性、边出结果边处理，用 imap / imap_unordered。
        results = p.map(cpu_work, nums)

    # ⚠️ 4 是硬编码的。更稳的写法是 Pool() 不传参（默认用 os.cpu_count()），
    # 或者显式 Pool(min(4, os.cpu_count()))。
    print(time.time() - t)             # 比单进程快约 4 倍
```

> ⚠️ 进程间通信比线程贵得多（要序列化），不要给小任务开一堆进程。

## 5. concurrent.futures：高级 API（推荐） 🎯

`threading` / `multiprocessing` 太啰嗦，`concurrent.futures` 给了一个统一接口：

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def fetch(url):
    import urllib.request          # 函数内 import：延迟加载。IO 密集场景无所谓，
                                   # 但惯例还是放模块顶部
    return len(urllib.request.urlopen(url).read())


urls = ["https://www.example.com"] * 10

# IO 密集 → 线程池
# 依据：urlopen 底层是 socket 操作，等待网络时会释放 GIL，
# 所以多个线程能真正并行「等」，而不是抢 GIL 空转。
# 换成 ProcessPoolExecutor 也能跑，但每个进程要初始化解释器，
# 对「就是等网络」这种任务，进程开销远大于收益。
with ThreadPoolExecutor(max_workers=5) as ex:
    # ex.map 立即返回「迭代器」，不阻塞 —— 和 multiprocessing.Pool.map
    # 返回 list 不同。任务在调用 map 时就已全部提交给线程池。
    # list(...) 在这里起到「消费迭代器 + 阻塞到全部完成」的作用。
    # 结果顺序与 urls 一致，不是完成顺序。
    sizes = list(ex.map(fetch, urls))

print(sizes)
```

只要把 `ThreadPoolExecutor` 换成 `ProcessPoolExecutor` 就能切到多进程，**接口一模一样**。

## 6. asyncio：Python 异步的银弹 🌟

**类比**：餐厅老板雇一个超能服务员（事件循环）。每次客人点完菜，他不站着等菜出锅，而是**立刻去招呼下一桌**。菜好了厨师按铃他再回来端。一个人服务 50 桌就是 asyncio。

### 关键概念

| 名称 | 作用 |
|------|------|
| **事件循环** event loop | 那个"超能服务员"，调度所有协程 |
| **协程** coroutine | 用 `async def` 定义的函数 |
| **await** | "我要等 IO，先暂停，让别人跑" |
| **Task** | 把协程包成"可调度的"对象 |

### 第一个异步程序

```python
import asyncio


async def hello(name, delay):
    print(f"{name} 开始")
    # await 是「让出控制权」的唯一位置：事件循环在这里切到别的任务。
    # 没有 await 的纯 CPU 代码（比如 for 循环算 10 秒）会阻塞整个事件循环，
    # 其他协程一行都跑不了 —— 这是 asyncio 最常见的误用。
    await asyncio.sleep(delay)         # 让出控制权给事件循环
    print(f"{name} 结束")


async def main():
    # gather 接收「协程对象」，把它们包装成 Task 并并发调度。
    # 注意：hello("A", 1) 只是创建协程对象，不会执行；
    # 真正开始执行是在 gather 内部把它们转成 Task 之后。
    # gather 返回「结果列表」，顺序与传入顺序一致 —— 这里没接，结果被丢弃。
    await asyncio.gather(              # 同时跑多个协程
        hello("A", 1),
        hello("B", 2),
        hello("C", 1),
    )


# asyncio.run：创建新事件循环 → 运行 main() → 关闭循环 → 清理残留任务。
# 只能在「主线程、且当前没有运行中的事件循环」时调用，
# 在已有事件循环里（比如 Jupyter、async 函数内部）调会抛 RuntimeError。
asyncio.run(main())
```

**运行结果**（总耗时约 2 秒）：
```
A 开始
B 开始
C 开始
A 结束
C 结束
B 结束
```

### async / sync 不能直接混！

```python
import time
import asyncio

async def fetch():
    time.sleep(3)             # ❌ 错！同步阻塞：整个事件循环被卡死 3 秒，
                              #    这 3 秒里没有任何其他协程能跑。
    await asyncio.sleep(3)    # ✅ 对！异步等待：立刻让出控制权，
                              #    事件循环去调度别的任务，3 秒后再回来。


# 上面两个 sleep 都写在一个函数里，是「对照」不是「示例」。
# 实际运行会先阻塞 3 秒、再异步等 3 秒，共 6 秒。
# 真正的对照要看两个独立的协程 —— 见下文「可跑版」。
```

> 💡 **划重点**：在协程里调用同步阻塞函数（`time.sleep` / `requests.get` / 复杂计算），等于"把超能服务员摁在椅子上 3 秒"。要么换异步库，要么用 `loop.run_in_executor` 把它扔到线程池。

## 7. 异步 HTTP：aiohttp / httpx ⚡

```python
# pip install aiohttp
import asyncio, aiohttp, time

async def fetch(session, url):
    # async with 是必须的，不是风格问题：
    # session.get(url) 返回的是上下文管理器，进入时 await 拿到 response，
    # 退出时把连接「释放回连接池」。不写 async with 直接 await session.get(...)，
    # 连接不会归还 —— 池耗尽后所有请求都会挂住。
    async with session.get(url) as r:
        # r.text() 要 await：读整个 body 是 IO。
        # 这里没有 r.raise_for_status() —— 4xx/5xx 也会正常返回 text，
        # 业务上通常要显式检查 r.status。
        return await r.text()

async def main():
    urls = [f"https://httpbin.org/delay/1" for _ in range(10)]
    # ClientSession 应该在「一个」async with 里创建、复用，
    # 它内部维护连接池 —— 每次请求新建 session 等于每次新建连接池，失去复用。
    async with aiohttp.ClientSession() as s:
        # *(gen) 把生成器解包成 10 个协程对象传给 gather。
        # 注意：这里只是「创建协程对象」，gather 内部才会把它们包成 Task 并调度。
        # gather 返回结果列表，顺序与传入顺序一致。
        results = await asyncio.gather(*(fetch(s, u) for u in urls))
    print("拿到", len(results), "个响应")


t = time.time()                        # ⚠️ 测量耗时应该用 time.perf_counter()
asyncio.run(main())
print("耗时", time.time() - t)         # 约 1 秒，10 个请求并发！
```

如果用 `requests` 同步抓，要 10 秒。

**同款代码的 httpx 版**（总纲章项目技术栈选的是 httpx，第 11 节直接用它）：

```python
# pip install httpx
import httpx

async def fetch(client: httpx.AsyncClient, url: str) -> str:
    r = await client.get(url, timeout=10)   # 默认读完整个 body —— 不会犯第 8 节"问题 A"
    r.raise_for_status()                    # httpx 有显式的 raise_for_status（aiohttp 没有）
    return r.text                           # 响应已读完，连接自动归还 —— 没有"问题 B"

async with httpx.AsyncClient() as client:   # 连接池复用，和 ClientSession 同理
    results = await asyncio.gather(*(fetch(client, u) for u in urls))
```

> 💡 aiohttp 要 `async with session.get(...) as r` 逐请求包一层才归还连接；httpx 默认非流式、读完即还，**不容易写出第 8 节那种反例**。日常抓取首选 httpx，需要 WebSocket / 细粒度流控再上 aiohttp。

## 8. 实战：同步 vs 多线程 vs 异步爬豆瓣 Top 250 🥊

```python
import time, requests, asyncio, aiohttp
from concurrent.futures import ThreadPoolExecutor

URLS = [f"https://movie.douban.com/top250?start={i*25}" for i in range(10)]
HEADERS = {"User-Agent": "Mozilla/5.0"}


# 1. 同步：一个接一个，总耗时 = 10 个请求之和
def sync_run():
    t = time.time()
    [requests.get(u, headers=HEADERS) for u in URLS]
    # ⚠️ 没检查状态码、没设 timeout。
    # ⚠️ 列表推导只是为了「副作用」，结果被丢弃 —— 用 for 循环更直白。
    print("同步:", time.time() - t)


# 2. 多线程：10 个线程并发
def thread_run():
    t = time.time()
    with ThreadPoolExecutor(10) as ex:
        # lambda 在线程池里能用 —— 因为线程共享内存，不需要 pickle。
        # （ProcessPoolExecutor 里 lambda 会直接炸，这是两者的关键区别。）
        list(ex.map(lambda u: requests.get(u, headers=HEADERS), URLS))
        # ⚠️ 同样没检查状态码、没设 timeout。
        # ⚠️ ex.map 返回迭代器，list() 只是为了「消费 + 阻塞到全部完成」。
    print("多线程:", time.time() - t)


# 3. 异步：10 个请求并发
async def async_run():
    t = time.time()
    async with aiohttp.ClientSession(headers=HEADERS) as s:
        # ⚠️ 问题 A：s.get(u) 只「建立连接、拿到响应头」，
        #    没有读 body —— 请求可能还没真正完成，计时偏短。
        # ⚠️ 问题 B：没有 async with 管理 response ——
        #    连接不归还连接池，10 个请求后就可能 hang 住。
        # ⚠️ 问题 C：gather 的返回值被丢弃，response 对象没人关闭。
        await asyncio.gather(*(s.get(u) for u in URLS))
    print("异步:", time.time() - t)


sync_run()
thread_run()
asyncio.run(async_run())
```

> ⚠️ **上面第 3 段（async）是故意写错的反例** —— 三个 ⚠️（问题 A/B/C）就是它的病根：不读 body、连接不归还连接池、response 对象没人关闭。
> 真实项目里请用第 7 节的 `fetch()` 写法：`async with session.get(url) as r: return await r.text()`，并配合 `Semaphore` 控制并发。
> **先看清错在哪，再抄对的。**

**典型结果**：
```
同步:    8.3 秒
多线程:  1.2 秒
异步:    0.9 秒
```

> 💡 异步比多线程更快、更省内存（一个线程默认 8MB 栈，1000 个协程才几 MB）。

## 9. asyncio.Queue 生产者消费者 🏭

```python
import asyncio, random

async def producer(q: asyncio.Queue):
    for i in range(5):
        # random.random() 返回 [0, 1)，平均 0.5 秒 —— 模拟「生产耗时不定」
        await asyncio.sleep(random.random())
        # await q.put(i)：队列满时才会挂起；默认 Queue() 无上限（maxsize=0），
        # 所以这里几乎总是立即返回 —— 但 await 不能省，
        # 换成有 maxsize 的队列，put 就会变成真正的「等空位」。
        await q.put(i)
        print(f"生产 {i}")
    await q.put(None)                  # 哨兵：通知消费者结束

async def consumer(q: asyncio.Queue):
    while True:
        # await q.get()：队列空时挂起当前协程、让出事件循环 ——
        # 不是「忙等」，也不阻塞其他协程。这是 asyncio.Queue 和 queue.Queue 的核心区别。
        item = await q.get()
        if item is None: break         # 用 is None，不用 `if not item`：0 是合法值
        await asyncio.sleep(0.5)       # 模拟消费耗时；这里让出，producer 能继续生产
        print(f"消费 {item}")

async def main():
    q = asyncio.Queue()                # 默认 maxsize=0 = 无限队列
    # gather 等两个协程都「自然结束」才返回。
    # 和之前 daemon 线程的例子不同：这里没有「主线程先退出、消费者被强杀」的风险，
    # 因为 producer 放完哨兵才结束，consumer 拿到哨兵才 break —— 两边都会走完。
    await asyncio.gather(producer(q), consumer(q))

asyncio.run(main())
```

### 🎯 动手练习 7.1
写一个异步爬虫：抓 https://httpbin.org/uuid 共 50 次，**最多 10 个并发**，计时。

<details>
<summary>👀 参考答案</summary>

```python
import asyncio, aiohttp, time


async def fetch(s, sem, url):
    # async with sem 等价于 acquire() + try/finally: release() ——
    # 异常路径也保证释放，不会因为某个请求失败而永久占住槽位。
    # 这是 Semaphore 的正确用法；手写 acquire/release 漏掉 release 就死锁。
    async with sem:                    # 信号量控制并发数
        # async with s.get(...) 保证连接归还连接池。
        # 不写的话，50 个请求会泄漏连接 —— 之前讲过的坑。
        async with s.get(url) as r:
            # r.json() 要 await：读 body + 解析 JSON 都是 IO。
            # ⚠️ 没有 r.raise_for_status()：4xx/5xx 也会尝试解析，
            #    body 不是 JSON 时抛 aiohttp.ContentTypeError（见第 3 条）。
            return await r.json()


async def main():
    sem = asyncio.Semaphore(10)        # 最多 10 个请求同时进行
    async with aiohttp.ClientSession() as s:
        urls = ["https://httpbin.org/uuid"] * 50
        # *(gen) 把 50 个协程对象解包给 gather。
        # gather 内部把它们全部包成 Task —— 50 个 Task 同时「启动」，
        # 但只有 10 个能进 sem，其余 40 个挂在 acquire 上等。
        # 结果顺序与 urls 一致，不是完成顺序。
        results = await asyncio.gather(*(fetch(s, sem, u) for u in urls))
    print(len(results))                # 50


t = time.time()                        # ⚠️ 应该用 perf_counter
asyncio.run(main())
print(time.time() - t)
```
</details>

**解析**：`Semaphore(10)` 像个 10 张通行证的口子，没拿到证就 await 等。

## 10. 定时任务：asyncio 周期调度 ⏰

```python
import asyncio, datetime

async def heartbeat():
    while True:
        # 每轮打印当前时间，然后挂起 1 秒。
        # await asyncio.sleep(1) 是唯一的「挂起点」—— 取消只能在这里生效。
        # 如果循环体里全是同步代码（没有 await），cancel() 永远等不到执行机会。
        print(datetime.datetime.now())
        await asyncio.sleep(1)         # 每 1 秒一次

async def main():
    # create_task 把协程包装成 Task 并「立即调度」——
    # 不等它跑完，控制权马上回到 main。
    # 和 `await heartbeat()` 的区别：后者会卡在这里等，heartbeat 是 while True，
    # 永远不返回，main 就永远执行不到下面的 sleep。
    task = asyncio.create_task(heartbeat())

    await asyncio.sleep(5)             # 跑 5 秒

    task.cancel()                       # 取消任务
    # ⚠️ cancel() 只是「发出取消请求」，不阻塞、不等待。
    #    真正的停止发生在 heartbeat 下次执行到 await 处（抛 CancelledError）。
    # ⚠️ 当前代码没有 await task —— main 立刻结束，
    #    依赖 asyncio.run 关闭循环时的兜底清理。

asyncio.run(main())
```

```python
# my_spider/core.py —— 先不求项目结构，一个文件跑通"输入→并发抓→解析→输出"
import asyncio, csv, json
from pathlib import Path

import httpx
from bs4 import BeautifulSoup

async def fetch(client: httpx.AsyncClient, url: str, sem: asyncio.Semaphore) -> dict:
    async with sem:                     # 并发闸门：同时最多 N 个在途请求（本篇 §9 练习 7.1）
        try:
            r = await client.get(url, timeout=10)
            r.raise_for_status()
            soup = BeautifulSoup(r.text, "html.parser")
            return {"url": url, "status": r.status_code,
                    "title": soup.title.get_text(strip=True) if soup.title else "",
                    "h1": [h.get_text(strip=True) for h in soup.select("h1")]}
        except httpx.HTTPError as e:    # 超时/4xx/5xx 都归 httpx.HTTPError，不让一个坏 URL 拖死全场
            return {"url": url, "status": getattr(e.response, "status_code", 0),
                    "title": "", "h1": [], "error": str(e)}

async def crawl(urls: list[str], concurrency: int = 10) -> list[dict]:
    sem = asyncio.Semaphore(concurrency)
    async with httpx.AsyncClient(headers={"User-Agent": "Mozilla/5.0"},
                                 follow_redirects=True) as client:
        return await asyncio.gather(*(fetch(client, u, sem) for u in urls))

def output(rows: list[dict], out: Path) -> None:
    if out.suffix == ".csv":
        with out.open("w", newline="", encoding="utf-8") as f:
            w = csv.DictWriter(f, fieldnames=["url", "status", "title", "h1", "error"],
                               extrasaction="ignore")   # 正常行没有 error 键
            w.writeheader(); w.writerows(rows)
    else:
        out.write_text(json.dumps(rows, ensure_ascii=False, indent=2), encoding="utf-8")

if __name__ == "__main__":
    import sys
    urls = Path(sys.argv[1]).read_text(encoding="utf-8").split()
    rows = asyncio.run(crawl(urls))
    output(rows, Path(sys.argv[2] if len(sys.argv) > 2 else "out.json"))
    print(f"完成 {len(rows)} 个 URL")
```

## 🐛 常见错误集合

| 错误 | 原因 | 解决 |
|------|------|------|
| `RuntimeError: There is no current event loop` | 没用 `asyncio.run` | 用 `asyncio.run(main())` 启动 |
| 协程里阻塞 3 秒整体卡 3 秒 | 用了同步 IO | 换 aiohttp / `run_in_executor` |
| `coroutine was never awaited` | 调了 `f()` 没 `await` | 加 `await` 或 `asyncio.create_task` |
| 多线程 `counter` 不对 | 没加锁 | 用 `with lock:` 包起来 |
| `Pool` 必须放 `if __name__ == "__main__"` | Windows/Mac 子进程会重新 import | 加上这行守卫 |
