# 如何高效学习编程（必读）

> 这一篇不是技术，但比任何技术都重要。**没读完第 00 章不要进第 01 章**。

## 🎯 本篇目标

- 理解为什么"看视频学不会编程"（三个陷阱 + 各自的解药）
- 建立你的**学习节奏与反馈系统**（每天 / 每周 / 每月 / 每章四个周期的固定动作）
- 会用 AI（Claude/Cursor）当**老师**而非**保姆**（会提问、会追问、会验收）
- 知道**环境配置**和 **Git 工作流**该去哪学（本篇给速查清单，完整版在第 02、03 篇）
- 产出**学习契约**和**学习仪表盘**（本篇的两项交付物）

> 📌 本篇是"方法论"，不重复讲工具。第 4、5 节给的是**够用就好的速查清单**；每条命令的原理、报错排查和完整安装步骤在 [[02-环境配置完全指南]] 和 [[03-Git与GitHub入门]]，那里才是权威版本。

## 1. 你为什么学不会？三个常见陷阱

| 陷阱 | 表现 | 解药 |
|------|------|------|
| **教程地狱** | 看了 N 门课，写不出 1 个自己的项目 | 70% 时间写代码，30% 看教程 |
| **复制粘贴幻觉** | 跟着抄能写，不看就空白 | 每个例子先关教程默写一遍 |
| **AI 依赖症** | 让 AI 直接给答案，不自己思考 | 先自己写 → 卡 15 分钟 → 再问 AI |

## 2. 学习循环（每节都按这个走）

```
读 → 仿 → 关掉教程默写 → 改造（加新功能）→ 写笔记教别人 → 一周后再回顾
 ↑                                                                ↓
 └─────────────── 复习不到位就回到"读" ─────────────────────────┘
```

## 3. 时间安排建议

零基础 → 源码级，**每天 3 小时是底线**。建议：
- 工作日：早起 1.5h（学新内容） + 通勤听播客 + 晚上 1.5h（写代码）
- 周末：6-8h 集中做项目，1h 写周报
- **每周必须 GitHub 有 5+ 天绿点**（commit 真实代码，不要刷）

### macOS / Linux 用户

```bash
# 1. Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. Git + GitHub CLI
brew install git gh
gh auth login

# 3. Python（uv 是 2025 后新标准）
curl -LsSf https://astral.sh/uv/install.sh | sh

# 4. Node.js（Homebrew 版的 nvm 是 shell 函数，不是可执行文件，必须先 source）
brew install nvm
export NVM_DIR="$HOME/.nvm"
[ -s "$(brew --prefix)/opt/nvm/nvm.sh" ] && . "$(brew --prefix)/opt/nvm/nvm.sh"
nvm install --lts
npm i -g pnpm

# 5. VS Code
brew install --cask visual-studio-code
```

## 5. Git/GitHub 必会 10 个命令（速查）

> 📌 这 10 条只是"够用"清单。**四大区域模型、每条命令的场景说明、SSH 配置、第一个 PR 实战、以及 4 个"后悔药"命令**（restore / reset / revert / reflog）全在 [[03-Git与GitHub入门]]。只会这 10 条遇到"提交错了怎么办"会束手无策，建议学完本篇直接进第 03 篇。

```bash
git init
git clone <url>
git add .
git commit -m "feat: ..."
git push origin main
git pull
git branch feature/x
git checkout feature/x
git merge main
git log --oneline
```

约定式提交格式：`feat: / fix: / docs: / refactor: / test: / chore:`

详见：[Conventional Commits](https://www.conventionalcommits.org/zh-hans/)

## 6. 怎么用 AI 当老师（关键）

### ✅ 好的提问

> "我写了这段 Python 函数想反转链表，但运行报错。报错是 X。我猜是 Y 的问题，对吗？请只**指出方向**，不要直接给代码。"

### ❌ 差的提问

> "帮我写一个反转链表的函数。"

**铁律**：
- **第一次遇到的概念**，必须先自己读官方文档 30 分钟，再问 AI。
- AI 给的代码**先逐行解释一遍**给自己听，再粘贴。
- 项目代码必须能**关掉 AI 从头写一遍**才算掌握。

## 🐛 常见错误

新手最大的浪费不是"学得慢"，而是"用错方式学"。下面 6 条是这一篇最容易踩的坑，每一条都有对应的解药。

| 错误现象 | 原因 | 解决 |
|---|---|---|
| 教程看了 30 小时，代码一行没写出来 | 熟悉性幻觉：看懂讲解 ≠ 会写代码 | 70% 时间写代码、30% 看教程；每看完一段就关掉教程默写一遍 |
| 让 AI 直接吐出完整答案，抄完就跑不通 | AI 依赖症：跳过了"自己想"这一步 | 15 分钟原则：先自己写 → 卡满 15 分钟 → 再问 AI，且要求它**只给提示不给答案** |
| 学习计划写得漂亮，一周后就断了 | 没有外部承诺，也没有可视化反馈 | 建立"每日 1 次 commit + 1 条学习日志"的最小闭环（见上文「7. 反馈系统」） |
| 收藏了 50 个仓库，一个都没读完 | 资源囤积 | 先完整读完 1 个再开下一个；每月做一次 star 清理 |
| 环境装到一半就放弃 | 环境报错消耗掉了大部分学习热情 | 照 [[02-环境配置完全指南]] 一步步做；报错先查该文件的「🐛 常见错误」节，别瞎搜 |
| 想提第一个 PR 却不敢下手 | 选错了靶子、不了解流程 | 用 [firstcontributions/first-contributions](https://github.com/firstcontributions/first-contributions) 这类专为新手设计的仓库练手（详见 [[03-Git与GitHub入门]]） |
