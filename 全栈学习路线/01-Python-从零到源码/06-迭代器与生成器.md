## 1. 一切从 `for` 循环说起 🚶

你已经写过无数次：

```python
for x in [1, 2, 3]:
    print(x)
```

但你有没有想过：Python **凭什么**知道要"一个一个"把元素拿出来？换成字符串、文件、字典也都能 for，背后到底有什么"统一接口"？

**类比**：你去自助餐厅取盘子。柜台口有个出盘机，按一下"咔哒"出一个，再按"咔哒"再出一个，出完之后亮红灯说"没了"。
- "出盘机" = **迭代器**（iterator）
- "整柜盘子" = **可迭代对象**（iterable）
- "按一下" = `next()`
- "亮红灯" = 抛出 `StopIteration`

---

## 2. iterable vs iterator：两个长得很像的家伙 🪞

| 概念 | 定义 | 例子 | 关键方法 |
|------|------|------|---------|
| **iterable**（可迭代对象） | 能"被 for"的东西 | list / dict / str / file | `__iter__()` 返回一个迭代器 |
| **iterator**（迭代器） | 真正"一个一个吐"的家伙 | `iter([1,2,3])` 的返回值 | `__next__()` 每次吐一个 |

```python
nums = [1, 2, 3]          # nums 是 iterable，但不是 iterator

# iter() 调用 nums.__iter__()，返回一个独立的迭代器对象。
# list 每次调用 __iter__ 都返回一个「全新的」迭代器 —— 所以 list 可以反复遍历。
it = iter(nums)            # 调用 iter() → 拿到一个迭代器

print(next(it))            # 1    ← next(it) 调用 it.__next__()
print(next(it))            # 2
print(next(it))            # 3

# 第 4 次调用：抛 StopIteration。
# ⚠️ 在脚本里这一行会直接终止程序，除非包在 try/except 里：
#     try: next(it)
#     except StopIteration: print("没了")
# 注意：耗尽后不是「返回 None」，也不是「只抛一次」—— 之后再怎么调都继续抛。
print(next(it))            # 抛 StopIteration
```

**运行结果**：
```
1
2
3
Traceback (most recent call last):
  ...
StopIteration
```

> 💡 **划重点**：`for x in nums:` 等价于 `it = iter(nums); while True: try: x = next(it) except StopIteration: break`。Python 帮你藏起来了 try/except。

## 3. 自己造一个迭代器 🛠️

迭代器协议只要求两件事：
1. 有 `__iter__` 方法，返回 `self`（迭代器自己）
2. 有 `__next__` 方法，每次返回下一个值，没了就 `raise StopIteration`

```python
class Countdown:
    """从 n 倒数到 1 的迭代器"""

    def __init__(self, n: int):
        # n 既是「初始值」，也是「迭代状态」——每次 __next__ 都会改它。
        # 这意味着 Countdown 实例是「一次性」的：耗尽后再遍历什么也没有。
        self.n = n

    def __iter__(self):
        # 返回 self：这是 iterator 协议的要求。
        # for 循环统一用 iter(obj) 拿迭代器，这样 obj 是 iterable
        # 还是 iterator 都能走同一条路径 —— 对 iterator 来说 iter(it) is it。
        # 如果这里返回一个新对象，那就变成 iterable 而不是 iterator 了。
        return self                       # 我自己就是迭代器

    def __next__(self):
        # 用 n <= 0 而不是 n == 0：n 传负数时也直接结束，不会返回负值。
        if self.n <= 0:
            raise StopIteration            # 没了，亮红灯
        # 顺序不能颠倒：先取当前值，再自减，最后返回取到的值。
        # 写成 return self.n; self.n -= 1 是错的 —— return 后面的代码不执行。
        # 写成 self.n -= 1; return self.n 也会错 —— 3 变成 2 返回。
        cur = self.n
        self.n -= 1
        return cur


for x in Countdown(3):
    print(x)          # 3 2 1
```

**运行结果**：
```
3
2
1
```

### 🎯 动手练习 6.2
写一个 `MyRange(start, stop, step=1)`，模仿 `range`。

<details>
<summary>👀 参考答案</summary>

```python
class MyRange:
    def __init__(self, start, stop, step=1):
        self.cur, self.stop, self.step = start, stop, step

    def __iter__(self):
        return self

    def __next__(self):
        if (self.step > 0 and self.cur >= self.stop) or \
           (self.step < 0 and self.cur <= self.stop):
            raise StopIteration
        v = self.cur
        self.cur += self.step
        return v

print(list(MyRange(0, 10, 2)))   # [0, 2, 4, 6, 8]
```
</details>

## 4. 生成器函数：写迭代器的"傻瓜模式" 🎁

写迭代器要写 4 个方法，太累。Python 给了一个超级简单的语法糖：**`yield`**。

**类比**：`yield` 就像电视剧的"暂停键"。普通函数 `return` 一次就结束、内存释放；带 `yield` 的函数遇到 `yield` 会**暂停**，把值"递"出去，函数的局部变量、行号都被冻结；下次 `next()` 时**从那一行继续跑**。

```python
# 天然可反复（每次调用新建生成器）
def countdown(n):
    while n > 0:
        yield n          # 把 n 递出去，函数暂停在这里
        n -= 1

for x in countdown(3): print(x)      # 3 2 1
for x in countdown(3): print(x)      # 3 2 1  ← 再次调用，新生成器

g = countdown(3)
list(g)                              # [3, 2, 1]
list(g)                              # []  ← 同一个生成器，已耗尽
```

> 💡 **划重点**：只要函数体里出现了 `yield`，这个函数就不再是"普通函数"，调用它**不会执行函数体**，而是返回一个**生成器对象**（一种迭代器）。函数体直到你 `next()` 才开始跑。

```python
g = countdown(3)
print(g)                # <generator object countdown at 0x...>
print(type(g))          # <class 'generator'>
print(next(g))          # 3
```

### 生成器函数 vs 普通函数

| 特性 | 普通函数 | 生成器函数 |
|------|---------|-----------|
| 关键字 | `return` | `yield` |
| 调用时执行函数体？ | ✅ 立即执行 | ❌ 返回 generator |
| 局部变量保留？ | ❌ 退出即销毁 | ✅ 暂停时冻结 |
| 内存占用 | 一次性算完 | 用一个算一个 |

## 5. 生成器表达式：一行写完一个生成器 ⚡

把列表推导的 `[]` 换成 `()` 就是生成器表达式：

```python
squares_list = [x*x for x in range(1_000_000)]   # 立刻算 1M 个数，吃几十 MB 内存
squares_gen  = (x*x for x in range(1_000_000))   # 一个都没算，几乎不占内存
# ⚠️ squares_gen 是「一次性」的：
# 这行 sum 把生成器耗尽，之后再想用它什么也拿不到
print(sum(squares_gen))   # 一边吐一边加，内存恒定
```

> 💡 **划重点**：当你只需要"一遍 for"做求和、最大值、连接，**永远优先用生成器表达式**。

### 🎯 动手练习 6.3
读一个 1GB 的 CSV，统计第 3 列数字之和，**内存不能超过 100MB**。

<details>
<summary>👀 参考答案</summary>

```python
def col3_nums(path):
    with open(path, encoding="utf-8") as f:
        next(f)                          # 跳过表头
        for line in f:                   # 文件对象本身就是迭代器，一行一行读
            yield float(line.split(",")[2])

print(sum(col3_nums("big.csv")))         # 整个过程只占一行的内存
```
**解析**：`open()` 返回的文件对象就是一个迭代器，配合生成器函数，你可以处理任意大的文件。
</details>

## 6. yield from：委托给"子生成器" 🪜

```python
def chain(*iterables):
    # *iterables 把调用方传的多个可迭代对象收成一个元组。
    # 外层 for 逐个取出每个可迭代对象，内层 for 逐个产出它的元素。
    # 这是最直白的「扁平化」写法，任何懂 for 的人都能读。
    for it in iterables:
        for x in it:
            yield x


# 等价写法（更短、更快、转发更彻底）
def chain2(*iterables):
    for it in iterables:
        # yield from 对普通 iterable（list/tuple/str）就是「内层 for + yield」的简写，
        # 但循环在 C 层跑，少了一层 Python 字节码，所以略快。
        # 对「生成器」而言它远不止简写 —— 还会转发 send/throw/close，
        # 并捕获内层 return 的值。
        yield from it


print(list(chain([1,2], (3,4), "ab")))    # [1, 2, 3, 4, 'a', 'b']
# str 也是 iterable，所以 "ab" 被拆成 'a'、'b' —— 这是符合预期的，
# 但如果传进来的是「一个字符串」而你以为它是一个元素，就会意外铺平。
```

`yield from it` 不仅省一层 for，还会**自动转发** `send/throw/close`，写复杂协程时是必需的。

## 7. 协程基础：`send()` / `throw()` / `close()` 📡

生成器除了能"吐"，还能"接"东西：

```python
def echo():
    while True:
        # 这行同时做两件事：
        #   1. yield 是「表达式」不是语句 —— 它有返回值。
        #   2. 暂停在 yield 处，把控制权交回调用方。
        # 语法上，`msg = yield` 的右侧没有值，所以「吐出」的是 None；
        # 下次 send(v) 时，v 成为整个 yield 表达式的值，赋给 msg。
        msg = yield                    # yield 表达式：右边是吐出的值，"接"的是 send 进来的
        print(f"收到：{msg}")


g = echo()
next(g)                                # 必须先"启动"到第一个 yield
# 为什么必须启动？函数体在第一次 next()/send() 前一行都没执行，
# 此时生成器还没跑到 yield，没有「等待接收」的位置。
# 直接 g.send("hi") 会抛 TypeError: can't send non-None value to a just-started generator。

g.send("hi")                           # 收到：hi
# send 的语义：把值送到暂停处，唤醒生成器继续执行。
# "hi" 成为 yield 表达式的值 → msg = "hi" → print → 循环 → 再次停在 yield。
# 返回值是「这次 yield 吐出的东西」—— 这里是 None（yield 右侧没值）。

g.send("hello")                        # 收到：hello
g.close()                              # 关闭生成器
# close 在 yield 处抛 GeneratorExit 异常，生成器若没 catch 就直接结束。
# 之后 next/send 都抛 StopIteration。
```

**运行结果**：
```
收到：hi
收到：hello
```

> 💡 这就是 **协程** 的雏形。Python 后来用 `async/await` 替代了它（第 07 篇详解），但理解 send/throw/close 对读老代码、读 asyncio 源码都很有帮助。

## 8. itertools：标准库的瑞士军刀 🔧

`itertools` 全是迭代器工具，**一个比一个好用**。

| 函数 | 作用 | 例子 | 输出 |
|------|------|------|------|
| `chain(a, b, ...)` | 串联多个可迭代 | `chain([1,2],[3,4])` | `1 2 3 4` |
| `islice(it, start, stop, step)` | 切片迭代器 | `islice(count(), 5, 10)` | `5 6 7 8 9` |
| `groupby(it, key)` | 按 key 分组（**先排序！**） | `groupby("aaabbc")` | `('a', aaa) ('b', bb) ('c', c)` |
| `product(a, b)` | 笛卡尔积 | `product("AB", [1,2])` | `A1 A2 B1 B2` |
| `combinations(it, r)` | 组合 | `combinations("ABC", 2)` | `AB AC BC` |
| `permutations(it, r)` | 排列 | `permutations("AB", 2)` | `AB BA` |
| `accumulate(it, func)` | 累计 | `accumulate([1,2,3,4])` | `1 3 6 10` |
| `cycle(it)` | 无限循环 | `cycle("AB")` | `A B A B …` |
| `takewhile(pred, it)` | 满足条件就取 | `takewhile(<5, count())` | `0 1 2 3 4` |
| `dropwhile(pred, it)` | 满足条件就丢 | `dropwhile(<3, [1,2,3,4,1])` | `3 4 1` |

```python
from itertools import chain, islice, groupby, product, accumulate

# chain：把多个 iterable 依次串起来。惰性 —— 取完第一个才碰第二个。
# 内部是 C 实现，比手写 `for it in xs: for x in it: yield x` 快。
print(list(chain([1, 2], [3, 4])))                 # [1, 2, 3, 4]

# islice：对「任意 iterable」做切片，返回迭代器。
# 关键价值是「能切生成器」—— 生成器不支持 [] 切片，islice 可以。
# 注意：不支持负数索引（不能 islice(x, -3, None)），因为它不知道总长。
print(list(islice(range(100), 5)))                 # [0, 1, 2, 3, 4]

# accumulate：累积归并。默认 func=operator.add → 前缀和。
# 也可以传 func=operator.mul 得阶乘前缀，或 lambda 自定义。
print(list(accumulate([1, 2, 3, 4])))              # [1, 3, 6, 10]

# product：笛卡尔积，等价于嵌套 for。
# product("AB", [1, 2]) ≡ for a in "AB": for b in [1, 2]: yield (a, b)
# 还有 repeat 参数：product("AB", repeat=2) 等价于 product("AB", "AB")
print(list(product("AB", [1, 2])))                 # [('A',1), ('A',2), ('B',1), ('B',2)]

words = ["apple", "ant", "bee", "bat", "cat"]
# ⚠️ groupby 前必须排序 —— 这不是风格建议，是语义要求。
# groupby 只合并「相邻」的同 key 元素，不排序就会得到多个重复的组。
# key=lambda w: w[0] 按首字母分组，排好序后 a/b/c 各自聚在一起。
words.sort(key=lambda w: w[0])                     # groupby 前必须排序！
for k, group in groupby(words, key=lambda w: w[0]):
    # group 是「迭代器」，必须在本次循环内消费完（这里用 list）。
    # 如果延迟到下一轮再读，group 已经失效 —— 见下文第 3 条。
    print(k, list(group))
# a ['apple', 'ant']
# b ['bee', 'bat']
# c ['cat']
```

**运行结果**：
```
[1, 2, 3, 4]
[0, 1, 2, 3, 4]
[1, 3, 6, 10]
[('A', 1), ('A', 2), ('B', 1), ('B', 2)]
a ['apple', 'ant']
b ['bee', 'bat']
c ['cat']
```

## 9. 实战：手写 itertools 核心函数 🏗️

```python
def my_range(start, stop=None, step=1):
    """range 的生成器版。

    与标准 range 的差异：
        - 标准 range 是序列（有 __len__ / __contains__ / 下标），
          这里是生成器，只可迭代一次。
        - 标准 range 强制 step 为 int，这里允许 float，
          但浮点累积有误差（0.1 * 3 != 0.3），不保证边界精确。
    """
    # 修复 1：step 为 0 时标准 range 在构造时就抛 ValueError，
    # 原版会静默返回空 —— 调用方以为「范围为空」，实际是参数错误。
    if step == 0:
        raise ValueError("step 不能为 0")

    # 单参数调用时按 range(0, start) 解释。
    # 用 stop is None 而不是 if not stop：stop=0 是合法调用。
    if stop is None:
        start, stop = 0, start

    cur = start
    while (step > 0 and cur < stop) or (step < 0 and cur > stop):
        yield cur
        cur += step


def my_enumerate(iterable, start=0):
    """enumerate 的生成器版。行为与标准版一致，无可挑剔。"""
    i = start
    for x in iterable:
        yield i, x
        i += 1


def my_zip(*iterables):
    """zip 的生成器版。行为与标准版一致（含「最短截断」和「多消耗」）。

    已知特性（与标准 zip 相同，非 bug）：
        最短截断时，靠前的迭代器会「多消耗」一个元素。
        例如 zip([1,2,3], "x") 之后再取 [1,2,3] 的迭代器，只剩 3。
    """
    # 修复 2：空参数时标准 zip() 返回空迭代器；
    # 原版 while True + 空 for 会无限 yield ()，死循环。
    if not iterables:
        return

    iters = [iter(it) for it in iterables]
    while True:
        result = []
        for it in iters:
            try:
                result.append(next(it))
            except StopIteration:
                # 任何一个耗尽 → 整体结束。
                # result 里已取到的元素被丢弃 —— 这就是「最短截断」。
                return
        yield tuple(result)


def my_chain(*iterables):
    """chain 的生成器版。"""
    for it in iterables:
        # 对普通 iterable 是「内层 for + yield」的简写（C 层循环，略快）；
        # 对生成器还额外转发 send/throw/close，并捕获内层 return 值。
        yield from it


# ---------- 验证 ----------
if __name__ == "__main__":
    print(list(my_range(5)))                              # [0, 1, 2, 3, 4]
    print(list(my_range(5, 0, -1)))                       # [5, 4, 3, 2, 1]
    print(list(my_enumerate("abc", 1)))                   # [(1,'a'),(2,'b'),(3,'c')]
    print(list(my_zip([1,2,3], "abc", [10,20,30])))       # [(1,'a',10),(2,'b',20),(3,'c',30)]
    print(list(my_chain([1], (2,3), "ab")))               # [1, 2, 3, 'a', 'b']

    # 修复 1 验证
    try:
        list(my_range(0, 5, 0))
    except ValueError as e:
        print("step=0 抛错:", e)                          # step=0 抛错: step 不能为 0

    # 修复 2 验证
    print(list(my_zip()))                                 # [] —— 不再是死循环

    # 已知特性：最短截断时左侧多消耗一个
    a = iter([1, 2, 3])
    print(list(my_zip(a, "x")))                           # [(1, 'x')]
    print(list(a))                                        # [3] —— 2 被吃掉了
```

## 10. 实战：1GB 大文件按行去重 🐘

```python
def unique_lines(path):
    seen = set()
    with open(path, encoding="utf-8") as f:
        for line in f:                  # f 是迭代器，一行一行来
            # rstrip("\n") 只去掉行尾的 \n。
            # ⚠️ 如果文件是 Windows 换行（\r\n），这里会留下 \r —— 见下文第 2 条。
            line = line.rstrip("\n")
            if line not in seen:        # set 查存在性 O(1)
                seen.add(line)
                yield line              # 惰性产出，调用方写一行、内存里就少一行


# 用法（边读边写，全程内存恒定）
with open("dedup.txt", "w", encoding="utf-8") as out:
    for line in unique_lines("big.log"):
        out.write(line + "\n")
```

> 💡 如果连 `seen` 集合都装不下（行特别多），可以换成 [Bloom Filter](https://en.wikipedia.org/wiki/Bloom_filter) 进一步省内存 —— 这一招在第 05 章《后端开发》的「缓存穿透」一节里还会再遇到。

## 🐛 常见错误集合

| 错误                                                   | 原因              | 解决                               |
| ---------------------------------------------------- | --------------- | -------------------------------- |
| `TypeError: 'generator' object is not subscriptable` | 生成器不能 `g[0]`    | 先 `list(g)` 再下标                  |
| 生成器只能 for 一次，第二次空                                    | 它**消费完就没了**     | 重新调用生成器函数                        |
| `StopIteration` 提前抛                                  | `__next__` 写错条件 | 仔细检查边界                           |
| `groupby` 结果不对                                       | 没有先排序           | `sorted(it, key=...)` 后再 groupby |
| `next(g)` 直接报错                                       | 生成器还没启动         | 先 `next(g)` 启动到第一个 yield         |
