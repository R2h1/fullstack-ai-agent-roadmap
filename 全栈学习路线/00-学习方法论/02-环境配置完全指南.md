# 环境配置完全指南

> 工欲善其事，必先利其器。在敲第一行代码之前，我们先把"厨房"准备好。

## 🎯 本章目标

- 知道"开发环境"到底指什么（而不是背下一个名词）
- 在 macOS 或 Windows(WSL2) 上把工具链一次装齐
- 装好 Python 3.13（uv）、Node.js LTS（nvm）、pnpm、Git
- 遇到 `command not found` / `permission denied` 能自己排查，而不是重装
- 知道 Linux 和 macOS 的权限模型不一样

---

## 一、什么是"开发环境"？🍳

想象你要成为一名大厨。在炒菜之前，你需要：

- 一个**厨房**（操作系统 + 终端）
- 一套**锅碗瓢盆**（编辑器、Git、包管理器）
- **食材库**（各种编程语言运行时，比如 Python、Node.js）
- 一个**菜谱本**（项目代码）

"开发环境"就是程序员的厨房。配置环境 = 把这些工具装好、摆好、调好。

⚠️ 新手最容易在这一步劝退自己。但只要按本文一步步来，**任何报错都有解**。遇到问题先深呼吸，再复制错误信息去搜索。

## 二、macOS 配置流程 🍎

### 2.1 安装 Homebrew（包管理器）

**什么是包管理器？** 想象成 macOS 的 App Store，但是命令行版。你说一句"我要装 Python"，它就帮你装好。

打开"终端"App（Spotlight 搜 `Terminal`），粘贴：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

> 国内网络慢可换清华镜像（搜 "homebrew 清华镜像"）。

装完后**重启终端**，运行：

```bash
brew --version
```

看到版本号就成功了。

### 2.2 安装 iTerm2（更好用的终端）

```bash
brew install --cask iterm2
```

**为什么不用系统自带终端？** iTerm2 支持分屏、热键、配色更舒服，是 macOS 程序员的标配。

### 2.3 安装 Oh My Zsh（命令行美化）

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"
```

装完后你的终端会变好看，并且支持智能补全。推荐主题：

```bash
# 编辑配置文件
nano ~/.zshrc
# 找到 ZSH_THEME，改成：
ZSH_THEME="agnoster"
```

保存（Ctrl+O，回车，Ctrl+X），然后：

```bash
source ~/.zshrc
```

### 2.4 自我检查 ✅

```bash
brew --version    # 应输出 Homebrew 7.x.x（当前最新 7.0.15）或更高
echo $SHELL       # 应输出 /bin/zsh
which zsh         # 应输出 /bin/zsh 或 /opt/homebrew/bin/zsh
```

## 三、Windows 配置流程 🪟

⚠️ **强烈建议用 WSL2，不要直接在 Windows 原生环境开发。** 90% 的教程是为 Linux/macOS 写的，WSL2 让你在 Windows 里直接跑 Linux。

### 3.1 启用 WSL2

按 `Win 键` → 搜索 `PowerShell` → 右键"以管理员身份运行"，输入：

```powershell
wsl --install
```

这条命令会自动启用功能并装上 Ubuntu。装完**重启电脑**。

重启后会自动打开 Ubuntu 终端，让你设置用户名和密码。

> 💡 **密码不会显示**——这是正常现象，不是键盘坏了。盲打输入即可。

### 3.2 更新系统

```bash
sudo apt update && sudo apt upgrade -y
```

`sudo` = "以管理员身份执行"，会让你输密码（就是刚才设的那个）。

### 3.3 装常用工具

```bash
sudo apt install -y curl wget git build-essential
```

### 3.4 装 Windows Terminal（可选但强烈推荐）

到 Microsoft Store 搜 "Windows Terminal" 安装。它能在一个窗口里管理 PowerShell + WSL + CMD。

### 3.5 自我检查 ✅

```bash
lsb_release -a    # 应显示 Ubuntu 24.04 LTS 或更新（noble 及以后；22.04 jammy 也能用）
git --version     # 应显示 git version 2.x.x
```

## 四、安装 Python（用 uv，不要用 Anaconda）🐍

### 为什么不用 Anaconda？

| 方案 | 优点 | 缺点 |
|------|------|------|
| Anaconda | 一键装齐 | 庞大臃肿、慢、生态封闭 |
| 系统 Python | 自带 | 不能乱装包，可能搞坏系统 |
| **uv** | 极快、现代、Rust 写的 | 较新（但已稳定） |

uv 是 2024 年开始流行的新工具，速度比 pip 快 10-100 倍，是当前**业界推荐**。

### 安装 uv

**macOS / WSL 通用：**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

重启终端后：

```bash
uv --version
```

### 用 uv 装 Python

```bash
uv python install 3.13
```

### 自我检查 ✅

```bash
uv python list           # 列出已装版本
uv run python --version  # 应输出 Python 3.13.x
```

## 五、安装 Node.js（用 nvm + pnpm）📦

### 为什么用 nvm？

不同项目可能要不同 Node 版本。nvm = Node Version Manager，可以一键切换。

> ⚠️ **三种方法只选一种执行**，别整段复制 —— 方法三开头会 `rm -rf ~/.nvm`，会把方法一/二刚装好的目录删掉。

#### 方法一（推荐）：Homebrew 装 nvm

省掉脚本下载和 PATH 配置，但 Homebrew 版 nvm 是 shell 函数，**装完必须 source 一下才能用**：

```bash
brew install nvm
```

然后把下面两行加进 `~/.zshrc`（Homebrew 版的 nvm 需要手动指路）：

```bash
export NVM_DIR="$HOME/.nvm"
[ -s "$(brew --prefix)/opt/nvm/nvm.sh" ] && . "$(brew --prefix)/opt/nvm/nvm.sh"
```

#### 方法二：官方安装脚本

v0.41.0（2026-11 发布）；国内网络可能中断。

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.41.0/install.sh | bash
```

#### 方法三：手动克隆安装（国内 gitee 镜像，兜底方案）

⚠️ 这两行里的 `rm -rf ~/.nvm` 会**清空已有的 nvm 目录**，只在你确实想重来一次时用：

```bash
rm -rf ~/.nvm
git clone https://gitee.com/mirrors/nvm.git ~/.nvm
```

克隆完同样要把下面两行加进 `~/.zshrc`：

```bash
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
[ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"
```

**重启终端**，然后：

```bash
nvm install --lts    # 装最新长期支持版
nvm use --lts
node --version       # 应显示 v26.x.x（当前最新 LTS v26.13.x）或更新
```

> ℹ️ 顺带一提：Node 的 LTS 版本号每半年往上跳一档（2024 年还是 v20，2025 年 v22，2026 年是 v26）。看到旧教程写 `nvm install 18` 或 `node v18` 别慌，那是写的时候的最新版；**用 `nvm install --lts` 永远拿到当前 LTS**。

### 装 pnpm（比 npm 更快的包管理器）

```bash
npm install -g pnpm
pnpm --version
```

| 工具 | 速度 | 磁盘占用 |
|------|------|----------|
| npm  | 慢   | 巨大 |
| yarn | 中   | 大 |
| **pnpm** | **快** | **小** |

## 七、🐛 常见错误

先查这张速查表，再往下看每一条的详细排查步骤。

| 错误现象 | 原因 | 解决 |
|---|---|---|
| `command not found: brew` | Homebrew 没装，或装完没重开终端 | 重开一个终端窗口；`which brew` 查路径；brew 在 `/opt/homebrew/bin`（Apple Silicon） |
| Homebrew 安装卡在 "Downloading..." 很久 | GitHub 直连慢 | 换国内镜像（清华/中科大），或在 `~/.zshrc` 里配 `HOMEBREW_BREW_GIT_REMOTE` |
| `uv: command not found` | uv 装在 `~/.local/bin`，但 PATH 里没有 | `export PATH="$HOME/.local/bin:$PATH"` 后 `source ~/.zshrc` |
| `nvm: command not found` | nvm 是 shell 函数，不是一个可执行文件 | 必须 `source ~/.zshrc`；确认 `~/.zshrc` 里有对应那两行——Homebrew 装的是 `[ -s "$(brew --prefix)/opt/nvm/nvm.sh" ] && . "$(brew --prefix)/opt/nvm/nvm.sh"`，脚本/克隆装的是 `[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"`；两行都没有就按第五章对应方法补上再 `source ~/.zshrc` |
| `nvm install --lts` 装的版本和预期差好几档 | Node LTS 每半年跳一档（2024 v20 / 2025 v22 / 2026 v26） | 不是装错了，用 `node -v` 看实际版本即可；教程里写 `nvm install 18` 只是历史快照 |
| `sudo apt install gh` 装出来的 gh 只有 2.4.0，`gh pr create --fill` 报错 | Ubuntu 22.04(jammy) 的包太旧（2021 年版） | 升级到 24.04 LTS(noble，包为 2.45.0+)，或按 [[03-Git与GitHub入门]] 里的官方 apt 源三条命令装最新版 |
| WSL 里装好的工具，在 Windows 终端里找不到 | Windows 和 WSL 是两套独立环境 | 统一在 WSL 的终端里操作；Windows Terminal 里选 Ubuntu 配置文件作为默认 |
| `zsh: command not found: oh-my-zsh` | Oh My Zsh 装到了别的 shell | 确认 `echo $SHELL` 是 zsh；否则用 `chsh -s $(which zsh)` 切换 |

### `command not found: xxx`

**原因：** 程序没装，或装了但不在 PATH 里。

**排查：**

```bash
which xxx          # 看路径
echo $PATH         # 看 PATH 包不包含
```

**解决：** 把工具的目录加到 `~/.zshrc` 或 `~/.bashrc`：

```bash
export PATH="$HOME/.local/bin:$PATH"
```

然后 `source ~/.zshrc`。

### `permission denied`

**原因：** 没权限。

**解决：** 加 `sudo` 重试，或检查文件权限 `ls -l 文件`，必要时 `chmod +x 文件`。

⚠️ **不要无脑 `sudo`！** 用户目录下的操作不应该需要 sudo。如果一个命令在你家目录都需要 sudo，说明前面操作错了。

### Homebrew 巨慢

换镜像。搜 "homebrew 中科大镜像" 跟着配。

### WSL 装好了打不开

PowerShell 管理员运行：

```powershell
wsl --update
wsl --shutdown
```

再重新打开。
